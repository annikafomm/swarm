Format Requirements

The web-tool is working with the anndata-format. This is a tutorial on how counts and scores should be saved.

Counts

  • Counts
    • Stored in anndata.X

Observations (per Spot)

  • Stored in anndata.obs (all observation columns will be shown, so make sure to clean your anndata before upload).

Genes (var)

  • Stored in anndata.var (all gene columns will be shown, so make sure to clean your anndata before upload).
  • Gene Symbols only

Spatial autocorrelation scores

  • Moran's I: stored in anndata.uns["moranI"] as DataFrame with columns:
    • I
    • pval_norm
    • var_norm
    • pval_norm_fdr_bh
  • Geary's C: stored in anndata.uns["gearyC"] as DataFrame
    • C
    • pval_norm
    • var_norm
    • pval_norm_fdr_bh

Cluster relationship scores

'cluster' is the column in anndata.obs choosen as cluster to calculate the score

  • Centrality scores: stored in anndata.uns["'cluster'_centrality_scores"] as DataFrame with columns:
    • degree_centrality
    • average_clustering
    • closeness_centrality
  • Co-occurrence probability: stored in anndata.uns["'cluster'_co_occurrence"] as dictionary with entries:
    • intervals: interval boundaries, array of shape (n_intervals - 1,)
    • occ: 3D array of shape (n_clusters, n_clusters, n_intervals) (Make sure to select the right num_intervals in Upload form)
  • Neighborhood enrichment: stored in anndata.uns["'cluster'_nhood_enrichment"] as dictionary with entries:
    • counts: array of shape (n_clust, n_clust)
    • zscore: array of shape (n_clust, nclust)

Gene set scores

  • Gene sets: stored in anndata.uns["genie_genesets"] and anndata.uns["sponge_genesets"] as dictionaries with format:
    • regulator: [gene1, gene2, ..., geneN]
  • AUCell: stored in anndata.obsm["aucell_scores_sponge|genie3"] as DataFrames with regulators as columns.
  • GSVA: stored in anndata.obsm["spongeffects_GSVA_scores_sponge|genie3"] as DataFrames with regulators as columns.
  • ssGSEA: stored in anndata.obsm["spongeffects_ssGSEA_scores_sponge|genie3"] as DataFrames with regulators as columns.
  • Viper: stored in anndata.obsm["viper_scores_genie3"] as DataFrame with regulators as columns.

Tangram

  • Cell type compositions: stored in anndata.obsm["tangram_ct_pred"] as DataFrame with cell types as columns.

LIANA+ scores

  • Ligand receptor relationships:
    • Cosine similarity: stored in anndata.obsm["ligand_receptor_cosine_similarity"] as array of shape (n_spots, n_interactions)
    • P-value: stored in anndata.obsm["ligand_receptor_p_value"] as array of shape (n_spots, n_interactions)
    • Category: stored in anndata.obsm["ligand_receptor_category"] as array of shape (n_spots, n_interactions)
    • NMF factors: stored in anndata.obsm["ligand_receptor_NMF_factors"] as DataFrame with factors as columns.
    • Global scores: stored in anndata.uns["ligand_receptor_global_scores"] as DataFrame with columns:
      • cosine_similarity_mean
      • cosine_similarity_std
      • ligand_receptor_morans: Moran's R score
    • Interaction names: stored in anndata.uns["liana_columns"]["ligand_receptor"] as array of shape (n_interactions,)
  • Cell type composition - TF activity similarity:
    • Cosine similarity: stored in anndata.obsm["cell_comp_tf_activity_cosine_similarity"] as array of shape (n_spots, n_interactions)
    • Category: stored in anndata.obsm["cell_comp_tf_activity_category"] as array of shape (n_spots, n_interactions)
    • Global scores: stored in anndata.uns["cell_comp_tf_activity_global_scores"] as DataFrame with columns:
      • cosine_similarity_mean
      • cosine_similarity_std
    • Interaction names: stored in anndata.uns["liana_columns"]["cell_comp_tf_activity"] as array of shape (n_interactions,)
  • TF activity:
    • ULM score: stored in adata.obsm["tf_activity_score_ulm"] as DataFrame with TFs as columns.
    • ULM p-adjusted value: stored in adata.obsm["tf_activity_padj_ulm"] as DataFrame with TFs as columns.
  • Pathway activity:
    • MLM score: stored in adata.obsm["pathway_activity_score_mlm"] as DataFrame with pathways as columns.
    • MLM p-adjusted value: stored in adata.obsm["pathway_activity_padj_mlm"] as DataFrame with pathways as columns.

Explanation of the scores

Squidpy scores

  • Spatial Autocorrelation scores
    • Is the expression of a gene clustered in space or more randomly distributed?
    • Moran's I (global correlation)
    • Geary's C (local correlation)
  • Cluster interaction scores
    • How do clusters of cells interact with each other?
    • Centrality scores
      • How structurally important is each cluster is in the tissue 'network'?
    • Neighborhood enrichment
      • Do certain clusters tend to be neighbors more often than expected by chance?
    • Co-occurrence probability
      • How often do two clusters occur within a given radius?

 

Gene set scores

  • GSVA
    • How are the genes in a gene set expressed compared to the rest of the genes?
  • ssGSEA
    •  like GSEA on each sample individually
    • Are the genes from this gene set enriched in this spot?
  • AUCell
    • How many genes of a gene set are highly expressed in this spot?
  • VIPER
    • How active is the regulator based on how active and coordinately regulated the target genes are?

 

Views

Different views for the hexagon map can be selected through a dropdown menu. The views visualize different types of regulatory information as well as the observation columns of the anndata

Gene Expression View

The user can visualize normalized gene expression for each spot in the map. A table appears underneath the main visualization, where rows represent genes, and autocor- relation scores such as Moran’s I or Geary’s C, along with p-values, are shown. Genes can be sorted by any column or filtered by name. Pressing the ”Show” button triggers a request to the backend that retrieves expression values for each spot and updates the main visualization.

Leiden Clustering View

The Leiden clustering view has specific properties that allow the user to analyze differ- ent spatial transcriptomics scores that are determined based on the clustering and/or a nearest neighbor graph built on the spatial data. When you click on a spot, the whole cluster will be selected instead of just a single spot. In the side panel, the cell-type composition, number of spots in the cluster, neighborhood enrichment scores, and centrality scores of the cluster can be viewed.

Regulatory Scores View

To explore important regulatory modules in specific tissue areas, the user is provided with the regulatory scores view, which is also visible when the website is first loaded. To integrate the regulatory information into the spatial map, upon selection of a gene set of the GENIE3 or SPONGE network, different types of scores can be visualized on the map. These scores show the importance of the gene set in a spot and can be compared directly on the map, allowing for the identification of tissue regions where a specific regulatory module shows higher activity.

LIANA+ Scores

For the bivariate LIANA+ scores, a table containing the global scores, such as mean and standard deviation of the local cosine similarities or Moran’s R, appears below the main visualization. Each row has ”Show” buttons for fetching and visualizing either the local scores, p-values, or categories. Unique features of the Views

GeneSet Subgraphs

In the Regulatory Scores View you are provided with a subgraph of the network that is based on the currently selected gene set in the geneset-dropdown menu. This subgraph is built from the geneset and the prefiltered GENIE3/Sponge network. After selecting all edges involving a gene set node, the edges are filtered for your weight/pvalue filter (slider above the graph). The MinEdges slider controls the size of the network by selecting the best MinEdges edges from the remaining network after filtering for your p-value/weight threshold. From these edges, the nodes and the real cutoff are inferred (if you have less nodes than MinEdges after filtering with weight/pvalue than cutoff will differ from what you selected in the slider). The parameter is called MinEdges,because the original edges of the nodes inferred from the best edges are re-added to the graph. So MinEdges essentially regulates the Number of Nodes by limiting the edges we take into account first and inferring the nodes from them. This ensures that the graph does not get too large but you can still assume that for a given all significant edges are displayed.

Co-Occurrence-Table

At the bottom of the Leiden-Cluster-View, the co-occurrence table will open, where the user can explore the co-occurrence of clusters in different bin-like intervals (default is 50 intervals). Therefore, this view does not just allow visualization of the clustering but also helps discover more complex patterns like how clusters of spots interact and whether they form organizational ’hubs’. This is specifically useful to understand tissue organization and how the cells in the spots act collectively.
